# Outsourcing Workflow

## Source model

Markdown files in this repository are the internal source of truth. Word and PDF briefs are generated external deliverables.

## Dependency order

1. Approve style, scale, palette, pivots, and detail density.
2. Approve character concept and silhouette.
3. Approve mechanic-defining key poses.
4. Produce full animation sheets.
5. Produce specialized VFX against approved poses and timing.
6. Build final arena/room composition around confirmed combat footprints.
7. Import into Godot and perform gameplay-scale review.

## Review stages

### Concept/key-pose gate

Required for minibosses, bosses, major NPCs, transformations, and any design with high downstream dependency.

### Sheet-level review

Review sheets, source files, timing notes, palettes, modular inventories, and UI/environment mockups.

### In-engine review

Test normal camera scale, mixed encounters, hazards, room transitions, UI overlap, boss phases, and performance conditions.

## Revision baseline

Working contractor briefs currently assume:

- Up to two sheet-level revision rounds
- One in-engine readability revision round
- Additional concepts/key-pose rounds only when explicitly stated
- New assets and implementation-driven redesigns handled as written change orders

## Commercial structure

- Quote, pay, review, and approve work per internal batch.
- Current template uses 30% at batch kickoff and 70% after final approval.
- Either party may pause between batches.
- A top-level milestone is a production goal, not an all-or-nothing delivery.

## Contractor continuity

If a new artist enters after Milestone 1, require a paid style-matching test before production. Approved prior assets remain binding visual targets.
